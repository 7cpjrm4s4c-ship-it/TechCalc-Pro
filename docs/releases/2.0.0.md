# TechCalc Pro 2.0.0

## Freigabe

TechCalc Pro 2.0.0 führt die Core-Runtime und den internen Framework-Kernel als Zielarchitektur ein. Die Version ist auf `main` integriert und in `package.json`, Manifest, Core-Version, Service Worker und Release-Readiness synchronisiert. Ein Produktionsdeploy wird durch diesen Repository-Stand allein nicht belegt.

## Umfang

- Die kanonische Runtime-Struktur ist auf `core/` und `modules/` ausgerichtet.
- `core/` ist der zentrale Ort für app-weite Verantwortlichkeiten wie Runtime, Routing, UI-Primitiven, Rendering, Daten, Storage, PDF, Number Handling, Events, UX-Policies und Diagnostik.
- `modules/` bleibt auf fachmodulspezifische Verantwortlichkeiten begrenzt: Metadaten, Konfiguration, Zustand, Schema, Berechnungslogik, Ergebnismapping, Reportadapter, Saved-Record-Adapter und modulbezogene Controller- oder View-Logik.
- Root-Level-`css/` und `assets/` bleiben als statische Ressourcenorte erhalten und werden nicht in Core verschoben.
- Der zentrale Datenpfad ist `core/data`; entfernte `js/`-Kompatibilitätspfade dürfen nicht wiederhergestellt werden.

## Architekturabgrenzung

- Der Framework-Kernel-Vertrag definiert Core als alleinige Quelle für app-weite Laufzeitverantwortungen.
- App-weite Rendering-, Lifecycle-, Routing-, Validierungs-, Storage-, PDF-, Daten-, Number-, CSS- und UX-Policies bleiben Core-Verantwortung.
- Fachmodule importieren aus dem jeweils engsten passenden Core-Pfad und erzeugen keine eigenen Plattform- oder Framework-Fassaden.
- Der äußere Directory Move und eine interne Core-Reorganisation werden getrennt betrachtet; dieser PR schließt die Runtime-Struktur und die dazugehörigen Guards ab.

## Qualität

- `npm run audit:framework-kernel` sichert den Framework-Kernel-Vertrag ab.
- `npm test`, `npm run test:f-gases`, `npm run test:en378`, `npm run test:flooding` und `npm run test:integration` bleiben die maßgeblichen Gates.
- Import-, Precache-, Release-Readiness-, Package-Hygiene- und Integrationsprüfungen wurden auf die neue Runtime-Struktur ausgerichtet.
- Der ausschließlich für Entwicklung vorgesehene Blob-Transformer-Worker ist durch einen eigenen Security Guard abgesichert.
- Der Playwright-GitHub-Actions-Workflow ist für die E2E-Gates wiederhergestellt.
- Die Netlify-NPM-Registry-Konfiguration ist explizit über `.npmrc` abgesichert.

## Release-Dokumentation

- Die fortlaufenden Release Notes werden unter `docs/release/RELEASE_NOTES.md` geführt.
- Diese Datei dokumentiert den in `main` integrierten Umfang von 2.0.0. Die vorherige Version 1.6.1 bleibt in den historischen Release Notes dokumentiert.
- Künftige Versionsänderungen müssen die Single-Source-Version, Manifest, Service Worker, Precache-Revision und Release-Readiness gemeinsam aktualisieren.

## Risiko- und Architekturbewertung

Die Änderung bleibt auf Runtime-Struktur, Architekturvertrag, Guards, CI-Konfiguration, Worker-Härtung und Release-Dokumentation begrenzt. Es wird keine neue Fachlogik eingeführt. Bestehende Modulverantwortlichkeiten bleiben erhalten; app-weite Verantwortlichkeiten werden konsistent über Core abgegrenzt.
